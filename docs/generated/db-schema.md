# Graph schema

Status: generated. Do not edit this file by hand.

Graphiti.Net has no relational database for the graph. The stored shapes are Neo4j node labels, relationship types, properties, and indexes.
This page lists them as the Neo4j save queries of the port write them.

The script `scripts/db_schema.py` reads these files:

- `src/Graphiti.Net/Core/Models/Nodes/NodeDbQueries.cs` for the node save queries.
- `src/Graphiti.Net/Core/Models/Edges/EdgeDbQueries.cs` for the edge save queries.
- `src/Graphiti.Net/Core/GraphQueries.cs` for the indexes.
- `src/Graphiti.Net/Core/Nodes.cs` and `src/Graphiti.Net/Core/Edges.cs` for the keys of the maps that a save query takes as one parameter.

Run `python3 scripts/db_schema.py` to write this page again. Run `python3 scripts/db_schema.py --check` to find out whether it is current.
The upstream definitions are in `graphiti_core/graph_queries.py`, `graphiti_core/models/nodes/node_db_queries.py`, and `graphiti_core/models/edges/edge_db_queries.py`.
The port keeps the same queries. The other graph databases use other forms of these queries, and this page does not list them.

## Save paths that store another form

The tables above give the form of the save of one object through its model class. The operations classes of the Neo4j driver have their own save methods, and three of them store another form, as upstream does.
The end-to-end values in `tests/Graphiti.Net.E2E.Tests/values/graph_types_e2e.json` hold what Python stored on Neo4j for each of them. The bulk save of `utils/bulk_utils.py` is not ported yet, and this page does not list it.

| Save path | Difference |
| --- | --- |
| `save_bulk` of the entity node operations | Each `Entity` node also gets a property `labels`, a list of its labels. |
| `save_bulk` of the entity edge operations | The `RELATES_TO` relationship gets the properties `source_node_uuid` and `target_node_uuid`, and not `source_uuid` and `target_uuid`. It gets no `reference_time` property. |
| `save` of the entity edge operations | The `RELATES_TO` relationship gets no `reference_time` property. |
